# BRIDGE-007 Tray pairing UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user run the Windows Bridge without a console and open a new pairing PIN window via a tray **Pair new device** action, without restarting the process.

**Architecture:** Hexagonal UX port `IPairingUx`. Application `TrayPairingPresenter` wires `PairNewDeviceRequested` → `PairingCoordinator.BeginPairingWindow()` and pushes PIN/status to the UX. Console adapter for Linux CI and debug. Windows `NotifyIcon` adapter is the production UI. Domain/protocol unchanged.

**Tech Stack:** .NET 8 Worker, `UseWindowsForms` on Windows only, xUnit, Conventional Commits.

## Global Constraints

- Conventional Commits: `feat|fix|refactor|test|docs|chore(<scope>): …`
- Hexagonal: WinForms stays in a host adapter; Core has no `System.Windows.Forms` reference.
- PIN: still CSPRNG, 5-minute window, 5-attempt lockout. Log PIN at Information once per window open; tray balloon may show PIN (required AC). Do not log PIN on accept/reject.
- Tests must pass on Ubuntu CI: no WinForms in Core.Tests. Tray WinForms tests either skip off-Windows or live in a Windows-only test project that CI can skip on Ubuntu — **prefer no WinForms tests**; test presenter + console UX instead.
- Files ≤300 lines; methods ≤60.
- Update BACKLOG BRIDGE-007, CURRENT_STATE, KNOWN_ISSUES KI-003 when ACs met.
- Never change `git config`. Do not implement TLS, mmap extras, or Apple apps.
- Default bind remains loopback.

### Task 1: IPairingUx + presenter (reopen window)

**Backlog:** BRIDGE-007 (partial — Core, testable)

**Interfaces:**
- `IPairingUx`: `void ShowPin(string pin, DateTimeOffset expiresAtUtc);` `void ShowStatus(string message);` `event Action? PairNewDeviceRequested;`
- `TrayPairingPresenter(PairingCoordinator pairing, IPairingUx ux)`: subscribe to `PairNewDeviceRequested` and call `BeginPairingWindow()` then `ShowPin` with the new PIN. Problem: `BeginPairingWindow` currently generates PIN internally and only logs it — presenter cannot ShowPin without either:
  - **Preferred:** change `BeginPairingWindow` to return `(string Pin, DateTimeOffset ExpiresAtUtc)` (or a small record `PairingWindow`) **and** call `ux.ShowPin` from presenter after reopen; Worker also calls ShowPin after first BeginPairingWindow.
  - Do not duplicate PIN generation.

### Task 2: NotifyIcon adapter (Windows host)

### Task 3: Wire host + hide console + docs

**Behavior:**
- `Program.cs`: register `IPairingUx` — Windows interactive → NotifyIcon; else ConsolePairingUx

WinExe on Windows hides console; Ubuntu must remain Exe.

```xml
<OutputType Condition="$([MSBuild]::IsOSPlatform('Windows'))">WinExe</OutputType>
<OutputType Condition="!$([MSBuild]::IsOSPlatform('Windows'))">Exe</OutputType>
```

Allow `SIMPULSE_BRIDGE_CONSOLE=1` documented in DEVELOPMENT to use Exe for debug (csproj cannot easily read env at build time). **AC says “without a console window”.** Must ship WinExe on Windows csproj condition as above. Logs still go to console subsystem which is hidden — user sees PIN in tray balloon. Structured logs: add `AddSimpleConsole` still works if debugger attached; also keep Information to EventLog? YAGNI — balloon is PIN UX; logs remain for `dotnet run` from CLI which can override OutputType.

`NotifyIcon` requires a message loop. Start a STA thread:

And create NotifyIcon on that thread.
